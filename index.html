1Overview and objectives

This project examines two pretrained models on the same collection of 20 photographs. No model is trained or fine-tuned: both are used with their fixed public weights, in evaluation mode and with gradients disabled.

  • Part 1 — a pretrained Vision Transformer. Using torchvision's vit_b_16 with the ViT_B_16_Weights.IMAGENET1K_V1 checkpoint, we implement patch extraction ourselves, trace how an image becomes a sequence of tokens, and evaluate the model's 1,000-class ImageNet predictions.
  • Part 2 — CLIP for image–text matching. Using OpenAI CLIP ViT-B/32, we implement the image–text similarity computation step by step and verify it against the model's built-in output, compare three prompt templates for zero-shot classification, and study the similarity structure of CLIP's image embeddings.

All numbers on this page come from the executed experiments. Where a result is exploratory rather than required, it is labeled supplementary.

4ViT patch visualization and model inputs

Dividing an image into patches

We wrote our own patch-extraction function using only tensor reshaping: an image of shape (3, 224, 224) is reshaped to (3, 14, 16, 14, 16), the axes are reordered to (14, 14, 3, 16, 16), and the result is flattened to (196, 3, 16, 16). With patch size P = 16,

N= 22416×22416 =14×14=196  patches.

Patches are numbered in row-major order (patch k lies in row ⌊k/14⌋ and column k mod 14), and each contains 3 × 16 × 16 = 768 raw pixel values. Automated tests confirm the shapes, the ordering, exact reconstruction of the image from its patches, and that every pixel belongs to exactly one patch.

From patches to the 197-token sequence

The patch grid above contains nothing learned. Inside the pretrained model, three learned components turn the patches into the encoder's input:

  1. Patch projection. Each flattened patch xp ∈ ℝ768 is mapped to a D = 768-dimensional embedding zp = W xp + b, with a learned W ∈ ℝ768×768. torchvision implements this as a convolution with kernel size and stride 16, which is the same linear map applied to every non-overlapping patch.
  2. CLS token. A learned vector is placed in front of the 196 patch tokens, giving 196 + 1 = 197 tokens. It contains no pixels; through self-attention it collects information from all patches, and its final state is the only input to the classification head.
  3. Positional embeddings. Self-attention treats its input as an unordered set, so a learned matrix Epos ∈ ℝ197×768 (one row per position, including the CLS position) is added to tell the encoder where each token came from.
z0= [xclass; Wx1+b; …; Wx196+b] +Epos ∈ℝ197×768
Table 4. Shapes along the input pipeline (one image).
StageShapeLearned?
Raw patches (our function)(196, 3, 16, 16)no
Flattened patches (our function)(196, 768)no
Patch embeddings (projection)(1, 196, 768)yes
+ CLS token(1, 197, 768)yes

Manual patches vs. learned projection. To connect the two, we multiplied our manually extracted, flattened patches by the model's projection weights. The result reproduces the model's own patch embeddings with a maximum absolute difference of 4.3×10−6, which is floating-point rounding. The patch length 3·16·16 = 768 and the model width D = 768 are equal for ViT-B/16 only by coincidence; they are different quantities.

What the fixed 1,000-class output cannot express

The model can only answer with one of the 1,000 classes it was trained on. It cannot describe a scene ("three riders with bikes on a mountain"), name a class it has never seen, or answer "none of these"; the softmax always distributes all probability over the same 1,000 classes, even for an image that matches none of them. ImageNet also contains overlapping or nested categories — tabby / tiger cat / Egyptian cat, cup / coffee mug, sports car / convertible / racer — and all three errors in Figure 4 are between such neighbors, so the unrestricted accuracy penalizes answers a person might accept. Asking about a different set of classes would require retraining the classification head.

No probability exceeds about 0.91. The documented training recipe for this checkpoint uses label smoothing (0.11) together with mixup and cutmix, which discourage probabilities close to 1, so these values should not be read as calibrated confidence.

6CLIP similarity implementation and numerical verification

CLIP has two separate encoders, f for images and g for texts, which map into the same 512-dimensional space. For N images and M candidate texts we implemented:

ui= f(xi) ‖f(xi)‖2 , vj= g(tj) ‖g(tj)‖2 , Sij= ui⊤vj Lij= eτSij , Pij= exp(Lij) ∑kexp(Lik) , y^i= arg⁡maxjPij

where τ is the checkpoint's learned logit_scale and the softmax runs over the candidate texts k (the row maximum is subtracted before exponentiating for numerical stability).

Verification against CLIP's built-in output

clip.load keeps the checkpoint's native FP16 weights on the GPU. We compared our logits with logits_per_image from CLIP's own forward pass, always within the same precision.

Table 8. Manual vs. built-in logits (20 images × 5 texts).
PrecisionPeak GPU memoryMax |manual − built-in|Predictions identical
FP16 (native)381 MiB0.0156yes
FP32652 MiB5.7×10−6yes

In FP16 the difference is exactly one rounding step (FP16 numbers between 16 and 32 are 2−6 ≈ 0.0156 apart); it arises because CLIP multiplies the scale into the image features before the matrix product. FP16 and FP32 logits differ by at most 0.034 and give the same predictions. Because FP32 fits easily in the 4 GiB GPU, all remaining CLIP experiments use FP32, where the manual logits agree with the built-in logits within the chosen tolerance of 10−4. Our softmax matches PyTorch's within 1.2×10−9, and cached image embeddings are identical to freshly computed ones. The cache is keyed on the model, CLIP commit, precision, preprocessing and the checksum of every image, so any change invalidates it.

7Image–text similarity heatmap

  • Cosine similarity measures the angle between two unit vectors and lies in [−1, 1]. CLIP's image–text cosines are small (here 0.12–0.32), and the correct text leads the best wrong text by only 0.06–0.14.
  • Logits multiply the cosines by the learned constant eτ = 100. This keeps the ranking but stretches the gaps: a cosine gap of 0.1 becomes a logit gap of 10.
  • Softmax probabilities exponentiate and normalize the logits across the candidate texts in each row. A logit gap of 10 becomes a probability ratio of e10 ≈ 22,000, which is why the probabilities are almost exactly 0 or 1.

Why probabilities depend on the candidate texts

The softmax normalizes over whatever texts are supplied. With the five classes, tabby cat receives probability 0.9998. When the correct text is removed, the softmax must still distribute all probability among wrong texts, and golden retriever receives 0.585 although its cosine similarity (0.212) is far below that of the removed correct text (0.305). Adding tiger cat and kitten lowers tabby cat to 0.951, mostly in favor of tiger cat (0.046). A CLIP probability is therefore relative to the candidate list, not an absolute measure of how well a text describes the image.

8Prompt wording comparison

All 20 images were classified with three templates, always with the same candidate order (golden retriever, tabby cat, sports car, mountain bike, coffee mug). The image embeddings are computed once; only the five text embeddings change between templates.

Changed predictions. None: the five classes are visually very different, so every template classifies every image correctly.

Changed scores. The wording changes every score. an image showing a {category} gives the largest margin for all 20 images, and the bare class name gives the smallest margin for 15 of the 20 (for the other five, a photo of a {category} is lowest). The largest margin changes are tabby_cat_02 (8.2 → 12.2), mountain_bike_03 (6.6 → 10.2) and tabby_cat_03 (7.1 → 10.7). Because every margin is above 5.9, the correct-class probability exceeds 0.997 everywhere, and the changes appear only in the third or fourth decimal (largest: mountain_bike_01, 0.9971 → 0.9999). A higher correct-class cosine alone does not imply a larger margin, because the template also moves the competing texts: for sports_car_02, a photo of a … gives the higher correct-class cosine, but an image showing a … gives the larger margin.

Supplementary — harder candidate list. Adding five confusable distractors (Labrador retriever, Egyptian cat, convertible, road bike, cup) gives 19/20 correct for every template. The single error is the same for all three: mountain_bike_01 is labeled road bike (correct-class probability 0.18–0.28). Even here the wording changed confidence but no prediction.

Why changing a prompt is not fine-tuning

All CLIP parameters stay frozen (no gradients, evaluation mode), and the image embeddings are identical for all templates. Changing the template only changes the input text and therefore the five text vectors vj that act as classifier weights. Fine-tuning would instead update the model's parameters with gradient descent on labeled data, permanently changing the encoders.

Interpretation

Similar images within a category. The most similar pairs are tabby cats: tabby_cat_01–tabby_cat_04 (0.894) and tabby_cat_01–tabby_cat_02 (0.892). Their backgrounds differ (pavement, grass, snow), but each shows a striped cat facing the camera and filling much of the frame. Among the mugs, the two close-ups of a mug of black coffee on a wooden table (coffee_mug_01, coffee_mug_04) are the most similar pair (0.873), so similar composition and setting also raise similarity.

Dissimilar images within a category. mountain_bike_04 is the outlier of its class (mean 0.600 with the other bikes; 0.539 with mountain_bike_01). The other bike photos show a single parked bike; this one shows three riders in protective gear on a mountain road with a chairlift and a wide landscape. golden_retriever_03 (an agility jump in an arena) is likewise the least typical dog (mean 0.733).

Unexpectedly similar images across categories. The five most similar cross-class pairs are all dog–cat pairs, led by golden_retriever_02–tabby_cat_04 (0.771). The mean dog–cat similarity (0.686) is as high as the mean similarity within the mountain-bike class (0.684). That pair shares neither color (an orange dog on a red floor against a yellow wall; a grey striped cat on grass) nor background, so the similarity is better explained by both images showing a furry pet animal. Sports cars are the most isolated class (mean 0.44–0.46 to the other classes), and their most similar non-car image is always mountain_bike_02 (up to 0.573), consistent with a broad "vehicle" grouping.

What the representation captures. In these examples the embedding mainly reflects the semantic category of the main object and broader groups (animals vs. vehicles). It also reflects scene content and composition (the multi-person mountain scene; matching close-up mug photos). We found no evidence that color dominates: high-similarity pairs often differ in color, and the red Ferrari F430 and the red-orange dog photo have a similarity of only 0.39. With only 30 within-class pairs, and with object, background and composition varying together in these photos, their separate effects cannot be isolated; cosine values also have no absolute meaning (even unrelated images here score at least 0.36), so only comparisons are informative.

10Successful, incorrect and uncertain examples (ViT)

Successful predictions

  • sports_car_01 (red Ferrari F430 at an outdoor car show): sports car with probability 0.910; the next classes, convertible (0.010) and car wheel (0.009), are related car concepts.
  • mountain_bike_01 (full-suspension bike against a brick wall): mountain bike with 0.907; the runner-up, disk brake (0.005), is a part visible on the bike.
  • All four golden retrievers are correct (0.863–0.890), including golden_retriever_04, where the dog is small and standing in a lake. Their second choices are other dog breeds (Irish setter for the dark-red golden_retriever_02, cocker spaniel for golden_retriever_04).

Incorrect predictions

  • tabby_cat_01 (grey striped cat on pavement) → Egyptian cat (0.894); tabby is second with 0.018. tabby_cat_02 (brown tabby on snow) → Egyptian cat (0.581), with tabby 0.173 and tiger cat 0.159. The three ImageNet domestic-cat classes together receive 0.925 and 0.913: the model recognizes a domestic cat but splits these overlapping coat-pattern classes differently from our labels.
  • coffee_mug_03 (white mug held in a hand outdoors) → cup (0.328), with coffee mug close behind (0.263); the two classes are near-synonyms.

Uncertain correct predictions

  • tabby_cat_03: tabby 0.335 vs. tiger cat 0.288; the cat is partly hidden by leaves.
  • sports_car_04: sports car 0.391 vs. convertible 0.263 (black Ferrari Testarossa).

For CLIP, every image was classified correctly with all three templates; its least confident cases are discussed through the logit margins in Section 8.

11Model comparison and limitations

Table 11. Accuracy on the 20 images. The rows answer different questions and are not directly comparable.
ModelDecision amongAccuracy
ViT-B/161,000 ImageNet classes (primary)85%

CLIP ViT-B/3210 candidate texts incl. distractors (supplementary), each template95%
  • Different questions. ViT chooses among 1,000 classes; CLIP chooses among five texts that we wrote. When ViT is also restricted to the five classes, it is correct on all 20 images too.
  • Training objectives. ViT learns to map an image to one of 1,000 fixed labels with cross-entropy. CLIP learns, with a contrastive loss, to place matching images and captions close together in a shared space, so new classes can be expressed as text at test time without changing any weights.
  • Training data. ViT was trained on ImageNet-1k (≈1.28 M images with human labels); CLIP on 400 M image–text pairs collected from the internet. CLIP's training data is much larger, less curated and not public, so overlap with our test images cannot be checked.
  • Candidate-label sets. ViT's errors (Egyptian cat, cup) are ImageNet classes that are simply absent from CLIP's five-candidate list; part of CLIP's apparent advantage here comes from the smaller, user-chosen candidate set. In the supplementary 10-candidate test, CLIP chose tabby cat over Egyptian cat for all four cats; whether this reflects the models or the difference between ImageNet's class definitions and everyday usage cannot be decided from 20 images.
  • Architecture. ViT-B/16 sees 196 patch tokens of 16×16 pixels; CLIP ViT-B/32 sees 49 patch tokens of 32×32 pixels.
  • Small dataset. With 20 images, one image is worth 5 percentage points, and four images per class cannot represent the variation within a class. These results describe these 20 photographs only and do not show that either model is generally better.
  • Selection and preprocessing. Wikimedia Commons photos tend to be well lit and centered, which probably makes the task easier than everyday photos; some may even appear in the models' training data. Both models see only the center crop. ViT probabilities are affected by label smoothing and CLIP probabilities by the candidate list, so neither is a calibrated confidence.

12Conclusion

A ViT turns a 224×224 image into 196 patch tokens plus a learned CLS token; our manually extracted patches, multiplied by the model's learned projection, reproduce its patch embeddings, and its learned positional embeddings encode the 2-D patch grid. On 20 images from five ImageNet classes, ViT-B/16 reached 85% top-1 accuracy over all 1,000 classes, and all three errors were between overlapping ImageNet categories. For CLIP, our step-by-step implementation of normalization, cosine similarity, learned scaling and softmax matches the built-in output to within 5.7×10−6 in FP32. All three prompt templates classified every image correctly; the wording did not change any prediction but consistently changed the logit margins, with an image showing a {category} giving the largest margin for every image. CLIP's image embeddings group the photos by class and by broader concepts such as animals and vehicles, and they are also sensitive to scene content and composition. These observations are limited to a small, hand-picked set of photographs and should not be generalized to a ranking of the two models.

Reproducibility

  • The experiments use only fixed public checkpoints in evaluation mode; inference is deterministic for fixed weights and inputs, and re-running the full pipeline reproduced identical predictions.
  • All library versions are pinned in a lock file; the environment is listed in Section 3.
  • Image integrity is checked against recorded SHA-256 checksums before every experiment.
  • CLIP image embeddings are cached with a key that includes the model, precision, preprocessing and image checksums.
  • Automated tests (32, all passing) cover patch extraction, metrics, the CLIP computation on synthetic tensors, and integration checks against both real checkpoints.
  • The implementation is submitted privately with the course submission and is intentionally not published on this site.
